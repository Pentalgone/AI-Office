# AI-Office — План завершения MVP и самостоятельной разработки

**Актуализация:** 27 ноября 2026 года  
**Рабочая ветка:** `ai-office-upgrade`  
**Основная ветка:** `main` (не изменять до приёмки)

## Главная цель

Как можно быстрее получить AI-Office, который принимает задачу на естественном языке, планирует её, создаёт и распределяет подзадачи, выполняет работу специализированными AI-сотрудниками, проверяет отчёты, исправляет недочёты и выдаёт готовый результат.

Следующая обязательная цель — дать Developer безопасный доступ к проектному workspace, чтобы он мог читать и изменять файлы, запускать фиксированный набор тестов, откатывать неудачные изменения и готовить проверяемые изменения в Git. Изменения, затрагивающие запуск, безопасность, базу данных и секреты, должны проходить контроль владельца.

## Правила разработки и поставки

1. Разработчик проекта работает непосредственно с GitHub в ветке `ai-office-upgrade` или отдельной feature-ветке.
2. `main` не изменяется и PR не объединяется без отдельной приёмки.
3. Пользователь не редактирует исходники вручную. Он получает цельный комплект файлов/архив и выполняет резервное копирование, установку и пользовательские проверки.
4. Не перезаписывать `.env`, `data/ai_office.db`, `.venv` и пользовательские файлы.
5. Все изменения SQLite — только аддитивными миграциями с проверкой наличия столбцов и сохранности данных.
6. Не выполнять команды shell, предложенные LLM. Для Developer используются только явно разрешённые файловые операции и фиксированные команды проверки.
7. Всегда различать: написано; прошло автоматические тесты; проверено на компьютере владельца.
8. Не объявлять функцию готовой до прохождения её критериев приёмки.

## Этап 2. Автономный рабочий цикл

**В работе.**

Поток:
1. Пользователь отправляет цель.
2. Director формирует и валидирует план.
3. Backend создаёт главную задачу и подзадачи.
4. Dispatcher назначает свободных сотрудников по навыкам.
5. Исполнители выполняют работу через LLM и инструменты.
6. Результаты поступают Director.
7. Director принимает отчёт или возвращает его на доработку.
8. Исполнитель повторяет работу в пределах установленного лимита.
9. Backend пересчитывает статусы.
10. Director формирует итоговый отчёт.

Реализована сохраняемая в SQLite очередь запусков:
- `POST /ai/tasks/{task_id}/run` создаёт или возвращает активный запуск;
- фоновый worker обрабатывает очередь;
- `GET /ai/runs/{run_id}` возвращает состояние и результат;
- при перезапуске незавершённые запуски возвращаются в очередь, а назначения со статусом in_progress сбрасываются в pending;
- выполнение назначений и проверка отчётов пока последовательные.

Дальше:
- вынести оставшуюся orchestration-логику из `main.py` в отдельный сервис;
- добавить ограниченный параллелизм независимых назначений;
- учитывать зависимости и отмену во время выполнения;
- ограничить число повторов и обрабатывать ошибки провайдера;
- добавить тесты полного цикла с подменённым LLM, без реальных API-ключей.

**Критерий:** один запрос запускает выполнение, проверку, доработку и итоговый отчёт; сбой не теряет состояние и не портит отменённые/завершённые назначения.

## Этап 3. Самостоятельная разработка

**Следующий главный приоритет после этапа 2.**

Создать Developer Workspace с ограниченными возможностями:
- читать только разрешённые файлы проекта;
- исключать `.env`, ключи, базу данных, виртуальное окружение, Git metadata и пользовательские данные;
- формировать структурированный план изменений;
- создавать патчи/изменения только в разрешённых путях;
- сохранять резервные копии или работать в отдельной рабочей копии;
- запускать только фиксированные команды: компиляция и тесты;
- собирать вывод тестов и возвращать его Director;
- автоматически откатывать неуспешный набор изменений;
- создавать отдельную Git-ветку и коммит только после успешных проверок;
- не мержить изменения в `main` без подтверждения владельца.

Не разрешать модели произвольный PowerShell/cmd, произвольные shell-команды, доступ к секретам или прямое редактирование рабочей базы.

**Критерий:** пользователь может поручить Developer небольшое изменение AI-Office; агент изменяет код в изолированной рабочей области, запускает тесты, показывает diff и готовит безопасную ветку.
